# Resources

Build resources for packaging WA Stay: the brand artwork, the generated icons and installer art, the NSIS script and the macOS entitlements. electron-builder reads this folder as `buildResources`. Only `icons/icon.png` and `icons/icon.ico` are copied into the packaged app (`extraResources`), because the running app loads nothing else; the rest are build inputs.

```
resources/
├── brand/                     # Logo source of truth (generated SVGs), banner, concept review set
│   ├── README.md              # What each file is, the concepts, recorded contrast values
│   ├── wa-stay-mark.svg       # Square mark on its sand plate, full colour
│   ├── wa-stay-mark-small.svg # Simplified mark for 16 to 32 px
│   ├── wa-stay-mark-mono.svg  # Mark in one colour (currentColor)
│   ├── wa-stay-lockup.svg     # Mark + "WA Stay" wordmark, full colour
│   ├── wa-stay-lockup-mono.svg
│   ├── readme-banner.svg/.png # 1280 x 640, also the GitHub social preview
│   └── concepts/              # Every logo concept, plus contact-sheet.png
├── icons/                     # Generated by npm run icons: do not edit
│   ├── icon.ico               # Windows: 16, 24, 32, 48, 64, 128, 256
│   ├── icon.png               # 1024 x 1024 (macOS converts it; notifications)
│   ├── 16x16.png … 1024x1024.png  # Linux set (linux.icon is this folder)
│   ├── installer-header.bmp   # NSIS header, 150 x 57, 24-bit BMP
│   └── installer-sidebar.bmp  # NSIS welcome/finish sidebar, 164 x 314, 24-bit BMP
├── installer.nsh              # Custom NSIS macros
└── entitlements.mac.plist     # macOS hardened-runtime entitlements
```

## The brand pipeline

Everything in `brand/` and `icons/` is generated. Never edit those files by hand; change the generator and run `npm run icons`.

| Step | File | What it does |
| --- | --- | --- |
| Brush engine | `scripts/brand/brushstrokes.js` | D1's seeded brushstroke generator. The logo's ocean stroke and coral glint are pulled with the same engine and specs as the nav underline, so they are one gesture. |
| Wordmark outlines | `scripts/brand/outline-text.py` → `scripts/brand/glyphs.json` | A one-off design step. It sets "WA Stay" in Fraunces (wght 600, opsz 72) and the banner tagline in Figtree, and converts them to path outlines, so no SVG depends on an installed font. It needs Python with fonttools, brotli and uharfbuzz; nothing in the build or CI runs it. Re-run it only when the wording or face changes. |
| Logo | `scripts/brand/logo.js` | Draws every concept, reading colours from `src/renderer/styles/tokens.css`, and writes the six brand SVGs plus `brand/concepts/`. `CONCEPT` names the concept that ships. |
| Rasters | `scripts/generate-icons.js` (`npm run icons`) | Writes the SVGs above, reads each one back (it stops and names the file if one is missing or not well-formed XML), then rasterises with sharp: the ICO, the PNG set, both BMPs, the banner PNG, the renderer copies and two contact sheets. |
| BMP writer | `scripts/lib/bmp.js` | sharp cannot write BMP, so this turns `sharp(...).raw()` pixels into 24-bit uncompressed BMP (bottom-up BGR rows padded to 4 bytes, alpha flattened). |

Run it from the repo root:

```bash
npm run icons
```

- It needs no network, and the output is deterministic: a second run on the same machine changes no bytes.
- The output is **committed**. CI never regenerates it, because librsvg's anti-aliasing differs between operating systems. The Windows build only checks that `icon.ico`, `icon.png`, `256x256.png`, `installer-header.bmp` and `installer-sidebar.bmp` exist.
- `src/renderer/assets/brand/logo-mark.svg`, `logo-lockup.svg` and `logo-mark-mono.svg` are byte copies of the brand SVGs, for the app (`components/brand/Logo.tsx`). A test fails if they differ.
- Review the result in `docs/design/brand/contact-sheet.png` (the shipping set) and `brand/concepts/contact-sheet.png` (all concepts) before committing.

**To ship a different concept,** set `CONCEPT` in `scripts/brand/logo.js` to another key of `CONCEPTS` (`roofline`, `sun-tent` or `monogram`) and run `npm run icons`. Every SVG, icon, bitmap and copy follows.

**When a D1 colour token changes,** the brand palette test fails until you run `npm run icons`, which re-reads `tokens.css`.

## Sizes and formats

| Output | Size | Format | Source |
| --- | --- | --- | --- |
| `icons/icon.ico` | 16, 24, 32, 48, 64, 128, 256 | ICO of 32-bit images, transparent corners | 32 and below from `wa-stay-mark-small.svg`, the rest from `wa-stay-mark.svg` |
| `icons/icon.png` | 1024 x 1024 | PNG with alpha | `wa-stay-mark.svg` |
| `icons/NxN.png` | 16, 32, 48, 64, 128, 256, 512, 1024 | PNG with alpha | as the ICO: 32 and below from the small mark |
| `icons/installer-header.bmp` | 150 x 57 | 24-bit BMP, BI_RGB, on white | Its own artboard: the lockup, right-aligned (NSIS shows it top right) |
| `icons/installer-sidebar.bmp` | 164 x 314 | 24-bit BMP, BI_RGB, on sand-50 | Its own artboard: the mark over the wordmark |
| `brand/readme-banner.png` | 1280 x 640 | PNG | `readme-banner.svg` |

Platform notes:

- **Windows (NSIS).** `installerHeader`, `installerSidebar` and `uninstallerSidebar` point at the `.bmp` files. electron-builder passes the path straight to `MUI_HEADERIMAGE_BITMAP` / `MUI_WELCOMEFINISHPAGE_BITMAP`, and NSIS loads only bitmaps there, so PNGs would render blank.
- **macOS.** There is no `.icns`. `mac.icon` points at `icons/icon.png` and electron-builder converts it (it needs 512 px or more). The DMG uses the app icon.
- **Linux.** `linux.icon` is the `icons/` folder; electron-builder picks the `NxN.png` files.

## Using the logo

The shipping mark is **Roofline sunset**: a sun-gold half disc setting into an Indian Ocean blue brushstroke, under an ink roofline chevron. The chevron is a place to stay and the A of WA; the stroke is its crossbar.

- **Clear space:** keep at least the height of the chevron free on every side of the mark or lockup. Nothing else (text, edges, other logos) goes inside it.
- **Minimum size:** the mark at 16 px, the lockup at 96 px wide. At 32 px and below always use `wa-stay-mark-small.svg` (the icon pipeline does this for you).
- **In the app,** use `<Logo variant="lockup" | "mark" />` from `src/renderer/components/brand/Logo.tsx`. It renders an image named "WA Stay"; pass `decorative` when the name is already said beside it.

| Do | Don't |
| --- | --- |
| Use the files from `brand/` (or the renderer copies) as they are | Redraw, trace, re-colour or re-space the mark or wordmark |
| Put the full-colour lockup on sand, white or another light surface | Put the full-colour lockup on photos, ocean or ink: use a mono version |
| Use a mono version in one palette colour, such as `fg-inverse` on ocean | Add shadows, outlines, gradients, glows or filters |
| Keep the mark's sand plate in app icons | Crop the plate into a circle, or rotate or stretch the mark |
| Keep the coral glint as the only coral in the mark | Add more coral, or a second brushstroke, near the logo |
| Set "WA Stay" in running text in the UI face | Re-type the wordmark in another font, or use the mark as a letter in text |

## Palette

Every colour in the brand SVGs is a D1 raw palette token from `src/renderer/styles/tokens.css` (a test enforces this). Rules and reasoning are in `docs/design/design-language.md`.

| Token | Hex | Role in the brand |
| --- | --- | --- |
| `ink-900` | `#15181D` | Roofline chevron, wordmark |
| `ocean-500` | `#3A74B8` | The painted stroke (the sampled brushstroke blue) |
| `sun-400` | `#E8B858` | The setting sun (decorative only) |
| `coral-400` | `#D05830` | The sun's glow on the water, the single coral accent |
| `sand-50` | `#FAF7F2` | Icon plate, banner and sidebar background |
| `sand-0` | `#FFFFFF` | Installer header background; the reversed mono colour on ocean |
| `ink-700` | `#3A3F47` | Banner tagline |

Contrast values for the lockup and mono variants are recorded in `brand/README.md`.
